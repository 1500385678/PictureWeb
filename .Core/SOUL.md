# PictureWeb Soul

> 灵魂定义 · 这个项目存在的理由

## 一句话

**建筑效果图库。** 多维标签结构化 + AI 语义搜 + 以图搜图,
让张勇在参考图、效果图、案例库之间不再靠记忆和文件夹翻找。

## 它是谁 / 不是谁

**是**
- 建筑师的参考图与效果图库
- 项目级(中建·玖上琅宸 / 好莱坞山豪宅 等)按子目录组织的素材池
- 多维标签检索(项目 × 场景 × 光线 × 空间 × 材质 × 情绪 × 建筑类型 × 渲染风格)
- FTS5 trigram 全文(tokenize="trigram",中文按 3 字符滑窗分词) + pHash 以图搜图 双引擎
- 端口 8081 的本地 HTTP 服务 · stdlib 零依赖

**不是**
- 不是云相册 / 不是 NAS 网盘
- 不是渲染器 / 不是建模工具
- 不是 Markdown 知识库(那是 ArchitectLib 别处的活)
- 不是公开服务(127.0.0.1 only)

## 它服务的对象

**主用户**:张勇(建筑师)
**协作 agent**:pictureweb-coder(写代码)、pictureweb-verifier(审代码)、长史(YYDS 灵魂,统筹)
**外部被引用**:启动清单 cron、04-启动清单 PictureWeb 行

## 三方命名一致性

| 维度 | 写法 |
|---|---|
| 正式名 | PictureWeb |
| 目录名 | PictureDb |
| 命令行 | pictureweb |

ID 校验时三种写法都要接受,见 IDENTITY.md 别名表。

## 灵魂细则

- **数据先于智能**:先把库填满、结构化、可检索,再谈 AI 扩写。空库 + GPT = 烧钱。
- **离线优先**:无网也能搜也能取图,网络只用来同步和偶尔调 AI。
- **增量式标签**:宁可缺标签,也不要错标签。空值比错值安全。
- **结构即文档**:库表结构是给张勇 + agent 看的文档,字段命名、注释、表关系都要人类可读。
