## P0 · 必改

### 0.1 `/image` 整文件读入内存(server.py:147-149)

```python
with open(path_abs, "rb") as f:
    return self._binary(200, f.read(), ctype)
```

`f.read()` 不分块。`abs_path` 是库里任何路径——如果将来错填了一个 1GB 的源文件,服务把这个文件**全部读进内存**才发,并发 N 个就是 N×1GB。127.0.0.1 也炸。

**改法(单文件 ≤10 行):**

```python
import shutil
self.send_response(200)
self.send_header("Content-Type", ctype)
self.send_header("Content-Length", str(os.path.getsize(path_abs)))
self.send_header("Access-Control-Allow-Origin", "*")
self.end_headers()
with open(path_abs, "rb") as f:
    shutil.copyfileobj(f, self.wfile, length=64 * 1024)
```

顺手解决 OOM 风险,也让大图能边读边发。

### 0.2 FTS5 schema 缺 `arch_type` 列(server.py 隐含 + migrate_p1p2.py:159-172)

夜间批 1 把 `arch_type` 拆表了(1NF 化),但**新的 FTS5 索引里没有 arch_type 列**。实际后果:用户搜"酒店",库里 `arch_type` 字段是 `hotel`,但 FTS5 看不到——除非 caption/description 显式提到"酒店"二字。

夜间批 1 报告里写"留接口给 arch_type",但迁移脚本里只 `DROP + CREATE`,**接口没留**。要补两个动作:

1. FTS5 schema 加 `arch_type` 列(重建索引)
2. 写入 `image_arch_types` 的触发器,顺手把 `images.arch_type` 同步过来(否则冗余字段会漂移)

**改法(ALTER 不可逆,直接重建):**

```sql
DROP TABLE images_fts;
CREATE VIRTUAL TABLE images_fts USING fts5(
    id UNINDEXED, caption, description, filename, project,
    scene, space, material, mood, light, arch_type,
    tokenize = "unicode61 remove_diacritics 2"
);
INSERT INTO images_fts (id, caption, description, filename, project,
                        scene, space, material, mood, light, arch_type)
SELECT i.id, i.caption, i.description, i.filename, i.project,
       i.scene, i.space, i.material, i.mood, i.light,
       COALESCE((SELECT GROUP_CONCAT(value, ' ')
                   FROM image_arch_types WHERE image_id = i.id), i.arch_type)
FROM images i;
```

## P1 · 强烈建议

### 1.1 `/image` 没有 path 边界检查(server.py:139-141)

```python
path_abs = row["abs_path"]
if not path_abs or not os.path.exists(path_abs):
    return self._json(404, {"error": "file missing on disk"})
```

DB 里 `abs_path` 是任意绝对路径。127.0.0.1 风险低,但**一旦哪天绑 0.0.0.0 或数据库被外部脚本注入路径**,就会变成 path traversal。建议加白名单根:

```python
ALLOWED_ROOTS = (
    os.path.expanduser("~/Mac/WorkTeam/05_Space"),
    os.path.expanduser("~/Pictures"),
)
real = os.path.realpath(path_abs)
if not any(real.startswith(r) for r in ALLOWED_ROOTS):
    return self._json(403, {"error": "path not allowed"})
```

### 1.2 错误参数触发 500(server.py:91,127,156)

`int(qs.get("limit", ["20"])[0])`、`id_s.isdigit()`——`?limit=abc` 直接抛 `ValueError` → 500。/phash 同样。三个端点都得加 try/except 转 400。

### 1.3 hamming_hex 错误 vs 不相似混在一起(server.py:36-42, 174-176)

```python
def hamming_hex(a, b):
    if not a or not b or len(a) != len(b):
        return -1
    ...
```

`/phash?other=xxx` 里 `d = -1` 时返回 `{"similar": false, "hamming_distance_to_other": -1}`——调用方分不清是「不相似」还是「格式错误」。

**改法:** 改用 `None` 区分,JSON 里 `similar` 仅在 `d is not None and d <= 10` 时为 true;`hamming_distance_to_other` 缺省而非 -1。
